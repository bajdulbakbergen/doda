## ЧАСТЬ 1 — Что нужно от заказчика

### 1.1. Минимум для демо (5 минут заполнить)

Если ТОО ещё не зарегистрировано — можно временно использовать выдуманные правдоподобные данные. Заполните файл `src/config/operator.ts`:

| Поле | Пример значения | Источник |
|---|---|---|
| `legalForm` | `"ТОО"` или `"ИП"` | Решение заказчика |
| `legalName` | `"ТОО «Doda Marketplace»"` | Решение заказчика (финальное название согласовать с юристом) |
| `bin` | `"123456789012"` (12 цифр) | Свидетельство о регистрации ТОО (после регистрации) |
| `legalAddress` | `"010000, Республика Казахстан, г. Астана, пр. Мангилик Ел, 55"` | Свидетельство |
| `director` | `"Иванов Иван Иванович"` | Учредительные документы |
| `directorTitle` | `"Директор"` | По уставу ТОО |
| `registrationCity` | `"Астана"` | Определяет подсудность споров |
| `supportEmail` | `"support@doda.kz"` | Будет настроен после покупки домена |
| `dpoEmail` | `"dpo@doda.kz"` | То же |
| `phone` | `"+7 (7172) 00-00-00"` | Контактный |
| `commissionPercent` | `5` | Решение заказчика |
| `taxRegime` | `"Общеустановленный"` | Бухгалтер |
| `vatRegistered` | `false` или `true` | Бухгалтер |

### 1.2. Полный пакет для бета-теста (когда юрлицо готово)

Когда заказчик зарегистрировал ТОО и готов запускать с реальными подрядчиками:

**Юридические данные (из свидетельства о регистрации):**
- [ ] Точное юр. наименование (с кавычками «», как в реестре)
- [ ] БИН (12 цифр)
- [ ] Юр. адрес с индексом
- [ ] Фактический адрес (если отличается)
- [ ] ФИО руководителя
- [ ] Должность руководителя (Директор / Генеральный директор)
- [ ] Дата государственной регистрации ТОО

**Финансовые данные (от бухгалтера + банка):**
- [ ] Налоговый режим (общеустановленный / упрощёнка / специальный)
- [ ] Плательщик НДС: да/нет
- [ ] Наименование обслуживающего банка
- [ ] БИК банка
- [ ] ИИК (расчётный счёт)
- [ ] Кбе банка (опционально)
- [ ] Размер комиссии платформы (% от суммы успешной сделки)

**Контакты:**
- [ ] Email общей поддержки (`support@doda.kz`)
- [ ] Email DPO — ответственного за персональные данные (`dpo@doda.kz` или `privacy@doda.kz`)
- [ ] Контактный телефон с кодом города
- [ ] Адрес для официальной корреспонденции (если отличается от юр.)

**Регистрация и лицензии:**
- [ ] Номер регистрации в Реестре операторов персональных данных (получается через egov.kz → Минцифры РК, бесплатно, ~5-10 дней)
- [ ] Свидетельство о торговой марке «Doda» (опционально, через КИС Минюста РК)
- [ ] Доменное имя (.kz, оформленное на ТОО заказчика)

**Брендинг (опционально):**
- [ ] Финальный логотип (SVG, PNG)
- [ ] Цвета бренда (если отличаются от текущего зелёного)

### 1.3. Что заказчик должен сделать сам (нельзя делегировать разработчику)

- [ ] **Зарегистрировать ТОО** на egov.kz (1-3 рабочих дня, бесплатно для ТОО на электронной подаче). Без юрлица невозможно заключать договоры и принимать платежи.
- [ ] **Открыть расчётный счёт** в банке РК (Halyk, Kaspi Business, Forte и др.) — 1-3 дня после регистрации ТОО.
- [ ] **Постановка на учёт по НДС** — при ожидаемом обороте >20 000 МРП в год (~78 млн ₸ в 2025). Опционально на старте.
- [ ] **Договор эквайринга** с банком для приёма оплаты комиссии — после открытия счёта.
- [ ] **Регистрация в Реестре операторов ПД** через egov.kz → Минцифры РК.
- [ ] **Заключить договор с разработчиком** (work-for-hire) с явной передачей всех IP-прав на код, дизайн, документацию.
- [ ] **Найти юриста** для финальной валидации юр. документов перед коммерческим запуском.

### 1.4. Что МОЖНО делать прямо сейчас, без данных заказчика

- Тестировать функционал платформы (регистрация, лоты, ставки, сделки)
- Показывать работающий прототип на текущем `doda-nine.vercel.app`
- Дорабатывать дизайн и UX
- Готовить маркетинговые материалы (landing pages, демо-видео)
- Параллельно с регистрацией ТОО — заказчик собирает базу первых ИП/ТОО подрядчиков

## ЧАСТЬ 2 — Что сделано по юридическим моментам

### 2.1. Юридические документы (8 шт., полнотекстовые)

Все документы написаны на русском в соответствии с законодательством Республики Казахстан. Заглушек нет — содержательные тексты с реальными ссылками на статьи ЗРК. Документы тянут реквизиты Оператора из `src/config/operator.ts` — заполнили один файл → все 8 документов обновились.

| Документ | URL | Объём | Основания |
|---|---|---|---|
| Пользовательское соглашение | `/legal/terms` | 15 разделов | ГК РК, ЗРК «О ПД», ЗРК «О защите прав потребителей» |
| Политика конфиденциальности | `/legal/privacy` | 15 разделов | ЗРК «О ПД» №94-V от 21.05.2013 |
| Согласие на обработку ПД | `/legal/personal-data` | По всем требованиям ст. 8 ЗРК «О ПД» | Идентификация Оператора, субъекта, категории ПД, перечень операций, цели, получатели, трансграничная передача, срок, отзыв |
| Публичная оферта | `/legal/offer` | 8 разделов | Ст. 393–396 ГК РК |
| Регламент проведения торгов | `/legal/tenders-rules` | 10 разделов | Описание механики аукциона |
| Регламент разрешения споров | `/legal/disputes` | 10 разделов | Досудебный порядок, сроки, обжалование |
| Правила публикации контента | `/legal/content-rules` | 10 разделов | Запрещённый контент, модерация, DMCA-like процедура |
| Cookie Policy | `/legal/cookies` | 6 разделов | Категории cookies, провайдеры, управление |

Все документы реализованы как версионированные TSX-компоненты в `src/features/legal/documents/`. При обновлении содержания — увеличить `version` в meta объекте документа, и пользователям с прошлой версией будет предложено повторное согласие.

### 2.2. Технические механизмы согласий

| Механизм | Реализация |
|---|---|
| **Cookie consent banner** | 3-кнопочный (Принять все / Только необходимые / Настроить с категориями: необходимые/функциональные/аналитические). Выбор сохраняется в `localStorage` на 365 дней. Файл: `src/features/legal/components/cookie-consent-banner.tsx` |
| **2 обязательных чекбокса на регистрации** | (1) ToS + Оферта, (2) Согласие на ПД + Privacy. Submit-кнопка отключена пока не отмечены оба. Файл: `src/features/auth/components/sign-up-form.tsx` |
| **Журнал согласий в БД** | Таблица `user_consents` (user_id, document_slug, document_version, accepted_at, ip, user_agent, source). Запись автоматически при signup через SECURITY DEFINER функцию `record_signup_consent` (10-минутное grace-окно). Файл: `supabase/migrations/0017_user_consents.sql`, `0019_consent_helpers.sql` |
| **Версионирование документов** | Каждый документ имеет `version` (semver). При изменении текста — увеличить версию. Pre-existing consents в БД ссылаются на конкретную версию. Файл: `src/features/legal/registry.ts` |
| **Право на экспорт данных** | `/account/privacy` → кнопка «Скачать мои данные» → JSON со всеми связанными данными (профиль, согласия, лоты, ставки, сделки, отзывы, посты, сообщения, верификации). По ЗРК «О ПД» ст. 26 |
| **Право на удаление аккаунта** | `/account/privacy` → запрос с подтверждением «УДАЛИТЬ» (литерально набрать слово) → запись в `account_deletion_requests` → грейс-период 30 дней (можно отменить) → анонимизация связанных данных. По ЗРК «О ПД» ст. 12 |

### 2.3. Доказательная база для заказчика (админ-панель)

Доступ только при `profiles.is_admin = true`. Не-админ получает 404. На всех страницах `robots: noindex`.

| URL | Что |
|---|---|
| `/admin` | Дашборд: всего пользователей, верифицированных, pending верификаций, лотов, сделок, **записей согласий**, заявок на удаление |
| `/admin/users` | Таблица всех зарегистрированных пользователей с кол-вом согласий и статусом |
| `/admin/users/[id]` | **Доказательная база по конкретному пользователю**: профиль, журнал согласий (документ, версия, timestamp, источник, IP), все заявки на верификацию, последние 50 audit-log действий, статус заявки на удаление |
| `/admin/verifications` | Pending заявки на верификацию ИП/ТОО с просмотром БИН/документов и кнопками Approve/Reject + обязательный комментарий ревьюера для отказа |

Назначение админа: после регистрации в Supabase SQL Editor выполнить
```sql
update public.profiles set is_admin = true where slug = 'ваш-slug';
```

### 2.4. Соответствие требованиям ЗРК «О персональных данных» №94-V

| Требование | Реализация |
|---|---|
| Согласие на обработку ПД (ст. 8) | Обязательный чекбокс на регистрации с явным согласием. Текст согласия — отдельный документ |
| Идентификация Оператора в согласии | В тексте Согласия и Privacy указаны юр. наименование, БИН, адрес, email |
| Перечень категорий ПД | Перечислены в Privacy и Согласии: email, пароль, БИН, УДЛ-скан, профильные данные, история действий, IP, cookies |
| Перечень операций | Указаны: сбор, запись, систематизация, накопление, хранение, уточнение, извлечение, использование, передача, обезличивание, блокирование, удаление |
| Цели обработки | Подробно перечислены в Privacy и Согласии |
| Получатели ПД | Указаны: другие Пользователи (публичные данные), Supabase, Vercel, платёжные провайдеры, гос. органы по запросу |
| Трансграничная передача | Явное согласие: Германия (Supabase EU), США (Vercel), ЕС (CDN/аналитика) |
| Сроки хранения | Указаны: профиль + 3 года, audit-логи 5 лет |
| Право на доступ (ст. 24) | Экспорт данных через `/account/privacy` |
| Право на исправление | Через `/account` редактируется профиль |
| Право на отзыв согласия (ст. 8) | Через удаление аккаунта `/account/privacy` |
| Право на удаление (ст. 12) | `/account/privacy` → заявка → 30-дневный грейс → анонимизация |
| Уведомление о breach в 72 часа (ст. 25) | Процедура описана в Privacy Policy |
| Меры защиты ПД (ст. 21) | HTTPS, шифрование БД, bcrypt паролей, 2FA TOTP, RLS, audit-логи, приватные buckets для документов |

### 2.5. Соответствие ГК РК и хозяйственному обороту

| Требование | Реализация |
|---|---|
| Публичная оферта (ст. 395-396 ГК РК) | Документ `/legal/offer` со всеми существенными условиями договора |
| Акцепт через конклюдентные действия | Регистрация на Платформе = акцепт |
| Существенные условия услуг | Размер комиссии, порядок оплаты, сроки, ответственность — всё в Оферте |
| Применимое право | Право РК (прописано в Terms, Оферте, Disputes) |
| Подсудность | По месту нахождения Оператора (город из operator config) |
| Досудебный претензионный порядок | Регламент разрешения споров: 30 дней на ответ, форма подачи через email/Личный кабинет |

### 2.6. Миграции БД

| Файл | Что |
|---|---|
| `supabase/migrations/0017_user_consents.sql` | Таблицы `user_consents`, `account_deletion_requests` + RLS |
| `supabase/migrations/0018_admin_access.sql` | `profiles.is_admin` + `current_user_is_admin()` функция + admin-RLS для consents/audit/verifications/blacklist |
| `supabase/migrations/0019_consent_helpers.sql` | SECURITY DEFINER `record_signup_consent` (10-мин grace) |

Применить через Supabase Studio SQL Editor или CLI `supabase db push`.
