02 / 20 Проблема

B2B-закупки в РК — раздроблены и непрозрачны

  • Заказчики гоняют запросы по WhatsApp и таблицам, теряют ставки и историю
  • Подрядчики не понимают, кто им конкурирует и за какую цену — нет прозрачности
  • Goszakup закрывает только госсектор; частный B2B остаётся без инфраструктуры
  • Profi.ru-формат заточен под физлиц; механики обратного аукциона нет
  • Юридическая база сделки строится с нуля каждый раз — нет шаблонов и доказательной базы
03 / 20 Решение

Один кабинет. Заказчик и подрядчик. Обратный аукцион.

Doda — это marketplace, где зарегистрированный пользователь одновременно может быть и заказчиком, и подрядчиком. Создаёшь лот → подрядчики делают ставки в realtime → выбираешь победителя → сделка трекается до закрытия.

04 / 20 Архитектура ролей

Заказчик / подрядчик — это действия, не роли

1

Гость

Каталог лотов, профили, блоги, история сделок — всё публично, индексируется в Google

2

Зарегистрированный

Сохранять, подписываться, писать в чат. Email + 2FA, восстановление пароля

3

Верифицированный

Создавать лоты, подавать ставки. ИП/ТОО + УДЛ через приватное хранилище, ручная модерация

Верификация триггерится в момент попытки действия, а не при регистрации — низкий барьер входа, фильтр по факту

05 / 20 Тендерное ядро

Обратный аукцион с защитой от снайперов

Realtime каскад ставок

Все ставки публичны, сортируются от лучшей в реальном времени через Supabase Realtime. Подрядчик видит свою позицию и конкурентов сразу

Anti-sniping

Ставка в последние 3 минуты до дедлайна → автоматически +5 минут к таймеру. Никто не выиграет на последней секунде

Лимит изменений

Подрядчик меняет свою ставку максимум 3 раза. Защита от «спам-демпинга»

Минимальный шаг

max(1000 ₸, 0.5% от лучшей цены). Дёргаться по 100 ₸ нельзя

Атомарность гарантирована: все правила реализованы в Postgres-функции submit_bid с оптимистическими блокировками. Гонок нет даже при тысячах одновременных ставок.

09 / 20 Коммуникации

Встроенный мессенджер, привязанный к лоту

Точки входа

  • «Написать» в посте или профиле
  • «Задать вопрос» в карточке лота — диалог привязывается к лоту
  • Реалтайм-доставка через Supabase

Приватные лоты

  • Заказчик пригласил подрядчика прямо из чата
  • Подрядчик видит баннер accept/decline на странице лота
  • После принятия — может подавать ставки

Антиспам: лимит 5 сообщений/день для неверифицированных, жалобы и блокировки заложены в схему.

11 / 20 Mobile

PWA + TWA: устанавливается как обычное приложение

PWA

Manifest, Service Worker, offline-страница, install prompt, bottom navigation на мобилке, safe-area-insets для iPhone X+

TWA для Android

Бандл готов через Bubblewrap: assetlinks.json в репо, twa-manifest.json настроен. Загружаешь .aab в Play Store — приложение из коробки

Native APIs

Web Share API для расшаривания лотов и постов, fallback на clipboard. iOS «Добавить на главный экран», Android install prompt

Подход экономит ≈$50-100K на разработке нативных приложений и год работы команды. iOS-нативка делается позже, когда появится трекшен.

13 / 20 Доказательная база

Согласия фиксируются атомарно — оспорить нельзя

На регистрации

Два обязательных чекбокса (Условия + ПД). Согласия передаются в user_metadata, DB-триггер атомарно пишет в user_consents в той же транзакции. Если запись не прошла — регистрация откатывается.

Cookie banner

3 категории (необходимые / функциональные / аналитика). PostHog инициализируется только если пользователь дал согласие на analytics. Для авторизованных — server-side запись с IP и User-Agent.

Admin-панель (доступ только админу)

Полная история согласий по каждому пользователю: документ + версия + время + IP + User-Agent + источник. Готовый отчёт для регулятора.

Право на удаление и экспорт

Пользователь скачивает JSON со всеми своими данными или запрашивает удаление с 30-дневным grace. Cron автоматически анонимизирует профиль после grace, блокирует вход.

14 / 20 Безопасность

OWASP-чек + защита персональных данных

Row-Level Security

На всех таблицах. Пользователь физически не может прочитать чужие данные через API

2FA (TOTP)

Полная реализация: enroll + challenge на signin. Совместимо с Google Authenticator, 1Password, Bitwarden

Приватный bucket

УДЛ/паспорта в отдельном bucket с RLS. Админ видит через подписанные URL с TTL 1 час

Аудит-логи

Все важные действия: создание лота, ставка, изменение статуса сделки, верификация. Полный трейл

Чёрный список БИН

DB-триггер блокирует регистрацию ТОО из чёрного списка ещё до создания заявки

Защита от open redirect

Все redirect-параметры валидируются — относительные пути только

18 / 20 Бизнес-модель

Три источника дохода

①

Комиссия с заказчика

5% (настраивается) от суммы успешной сделки. Платится после закрытия — нулевой барьер входа для заказчиков

②

Платное продвижение постов

Boost постов в ленте, выделение в каталоге лотов. Подрядчики готовы платить за лиды

③

Подписки (Phase 3)

Premium-аккаунт для подрядчиков: расширенная статистика, приоритет в фильтрах, белый лейбл

Эскроу намеренно отложен — требует лицензии НБ РК. Сделки трекаются off-platform, статус ведётся в БД. После трекшена можно подавать на лицензию.
